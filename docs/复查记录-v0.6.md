## 逐项说明

### 1) 追加消息复检
`agent._respond()` 的原实现只在生成**前**做一次价格/库存判定，循环里只在客户改口时重取工具和知识，不再判定依据。
现在把「取工具 → 取知识 → 媒体 → 依据判定」整体放进循环顶部，任何一次消息变化都会走完整判定；判定为 `handoff` 时同时 `_drop_pending(peer)`，
避免同一批消息的旧草稿还能被人批准出去。

### 2) 依据判定从"价格关键词"扩到 9 类
新增 `wxreply/brain/evidence.py`，每类都有 `ask`（客户在问什么）和 `proof`（依据里必须出现什么）两组词。
判定逻辑：命中 `ask` 的类别，必须被「工具结果（ok）」或「知识片段（含该类 proof 词）」覆盖；否则
- 缺的是可问清楚的字段（型号/数量）→ 发固定追问（`rule` 模型，模型不能改写）；
- 问不清楚（配送/售后/规格/认证/账期/交期/公司/定制…）→ 转人工并暂停该会话自动回复。

另外有一道**数字溯源**：回复里的「数字+单位」必须能在客户原话或依据里找到，找不到就拦截并转人工。
这条能挡住"知识库只说会配送，模型自己补一个运费 88 美金"。

### 3) 图片出口
`_read_items()` 不再把 `detect_media` 绑到 `vision.available`（原来没有视觉模型时连"对方发了图"都不知道）。
`_describe_media()` 写入 `media_state`：`detected`（检测到但没取到文件）/ `unavailable`（没配视觉模型）/ `failed`（识别失败）/ `understood`。
`_media_verdict()`：第一次遇到读不出的图 → 固定追问"方便用文字说一下型号或需求吗"；同一张图（按文件路径/坐标去重）再来 → 转人工。

### 4) 工具结果类型
草稿里原来存 `[r.as_dict() for r in tool_results]`，重新生成时又按对象读 `.ok` → `AttributeError`。
现在草稿存对象，`ToolResult.coerce()` 双向兼容，`_generate()` 入口和 `regenerate_pending()` 都 coerce。

### 5) 草稿版本
- 新建草稿：`draft_id` + `draft_version=1` + `event_seq`；
- 重新生成：换新 `draft_id`，`draft_version+1`，并先复核"客户有没有新消息"（有就返回 `stale`）；
- 批准：`draft_id` 必填且必须相等，`event_seq`（若传）必须相等，否则 `blocked` / `stale`；
- 控制台快照把 `draft_id / draft_version / event_seq` 回传给前端；前端发送时带上，没草稿就禁用按钮。

### 6) WeKnora
按官方文档改正了 URL、认证头、条数参数和知识范围；错误按 HTTP 状态码 + `error.code` 归类（401 "API Key 无效"、403 "无检索权限或超出范围"、409 "缺少 X-Tenant-ID"）。
**仍未联通真实服务**：需要部署后做建库 → 索引 → 检索 → 无命中/401/超时的实机联调，见 `docs/接入方案.md`。

### 7) PaddleOCR
3.x 的 `OCRResult` 是 dict 子类且内容在 `'res'` 下（不支持 `res.rec_texts` 属性访问），解析器同时认
`{'res': {...}}`、扁平 dict、`page.json`、`rec_boxes` 单行框、2.x 的 `[[box, (text, score)]]`。
初始化参数按 3.x（`use_textline_orientation` 等）→ 2.x（`use_angle_cls/show_log`）→ 最小参数依次尝试。
**仍未做真实截图验收**（本机未安装 paddlepaddle，只有格式回放）。

### 8) 依据质量与追溯
- `Chunk` 增加 `score / chunk_id / meta`；本地检索用 `dataclasses.replace` 返回带分数的副本（不改共享对象）；
- 远端解析 `knowledge_title / knowledge_filename / knowledge_id / chunk_id / knowledge_base_id / metadata`；
- 有正分命中时丢弃 0 分片段（避免"返回任意片段 = 有依据"）；
- `kb/` 切块改为按 Markdown 标题切（原来整份 FAQ 会合成一块，导致任意问题都能"覆盖"所有主题）；
- 草稿 `knowledge` + 审计 `events/sends` 的 `kb_provider/kb_version/kb_sources` 记录"用了哪一版、哪几个片段、分数多少"；
- 多轮指代：记住本会话确认过的型号，`这个多少钱` 会把历史型号拼进检索 query；出现多个候选型号时先追问。

### 9) 凭据撤销
- `settings.json` 里空值不再被过滤，而是记入 `revoked`；
- `AIConfig.key_for()` 的优先级：显式撤销 → 模型自己的 key → 同网关顶层 key；`default` 撤销只切断继承，不影响重新录入；
- 「撤销全部凭据」把 `*` 展开成"所有已保存模型 key + default + vision + embedding"，不留通配符死角；
- 撤销后重建 `VisionClient / EmbeddingClient / KnowledgeBase / ModelRouter`，`ready` 立即变 false；
- 控制台令牌（`WX_CONSOLE_TOKEN`）被撤销后，带该令牌的请求直接 403，需要重启并配置新令牌。

## 回归

上一轮已修的问题全部有对应用例并通过：发送等待中关 live / 暂停 / 移除白名单均不发送；短输入框草稿被拦截；后台暂存草稿能补发；
跨供应商不继承 Key；未知产品/超档位报价拒绝；无关检索返回空；Embedding 缓存区分端点与模型；工具轮次预算独立；
摘要按客户计数；损坏接管状态阻止发送；工作线程死亡健康检查 503；Origin 精确拦截；快速切换客户清空草稿。
