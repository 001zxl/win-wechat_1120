# 外部项目接入方案（WeKnora / PaddleOCR / personal_wxwork_ZTS）

> 结论：**不整体替换**现有微信视觉桥，只按模块接入。本机现状：16GB 内存 / 28 线程 / 剩余 168GB / **未安装 Docker**。

## 一、三个项目怎么用

| 项目 | 定位 | 在本项目里的落点 | 是否现在接 |
| --- | --- | --- | --- |
| **WeKnora** | 知识库后端：文档导入、混合检索、来源引用、分块编辑 | `wxreply/brain/kb_weknora.py` + `rag.provider=weknora`，检索结果转成本地 `Chunk`，答案与来源走同一套生成/审计 | **先留接口，不部署**。等 FAQ 超过 ~200 条或需要业务同学在界面上维护时再上 |
| **PaddleOCR** | 文字/表格/单据识别 | `wxreply/perception/ocr.py` 增加 `PaddleOcrBackend`，配置 `runtime.ocr_backend=paddle` 切换，未安装自动退回 RapidOCR | **已留开关**，先用真实截图做 A/B 再决定默认值 |
| **personal_wxwork_ZTS** | 客服分流参考实现（质量门控、人工队列、上下文） | 只借鉴设计：证据优先的闸门、每客户最新待处理项+过期、分流原因落审计。相关能力本项目已有雏形（guardrails / handoff / audit） | **不安装**，按设计对照补齐 |

## 二、已落地的接入缝（本轮代码）

1. **知识库后端可切换**：`config.rag.provider = local | weknora`，`weknora_base_url / api_key / search_path`；
   远端不可用或返回空时**自动回退本地 BM25**，并在事件里提示，不会静默变成“没有知识”。
2. **OCR 后端可切换**：`runtime.ocr_backend = auto | rapidocr | paddle`；
   显式选 `paddle` 但没安装时自动退回 RapidOCR，`ocr.load_error` 里写明原因。
3. **证据优先的分流**：价格/库存类问题如果“工具没查到 + 知识库没命中”，直接转人工并暂停该会话自动回复，不再让模型自由发挥。
   （`no_evidence` 会进接管队列，控制台可一键“恢复自动”。）
4. **知识库版本与重载**：`kb.version`（内容哈希）+ `kb_reload` 动作；Embedding 缓存按「供应商+模型」命名空间隔离。

## 三、分阶段推进

### 阶段 1（现在就能做，不需要 Docker）
- 用 10~20 张真实微信截图，对比 RapidOCR 与 PaddleOCR：小字、数字、型号、多行气泡。
  - 装 PaddleOCR：`.venv\Scripts\python -m pip install paddlepaddle paddleocr`
  - 切换：`config.yaml` 里 `runtime.ocr_backend: paddle`，控制台状态会显示 OCR 后端与错误原因。
- 整理 30~50 条真实 FAQ（产品/用法/物流/售后/购买流程），每条含：适用 SKU、答案、来源、负责人、有效期、是否允许自动回答、转人工条件。
- 先跑 **BM25 + 人工确认**，用脱敏真实对话验证召回与话术。

### 阶段 2（知识库需要“业务同学自己维护”时）
- 部署 WeKnora。两种方式：
  - **Docker Desktop（WSL2）**：本机 16GB 内存可以跑标准版（官方建议 4C/8G），但会常驻占用 2~4GB；
  - **另一台机器/NAS**：更推荐，微信这台保持轻量。
- 接好后：`rag.provider: weknora`、填 `weknora_base_url`、`api_key`，先在控制台用「模拟测试」比对本地与远端检索结果。
- 需要按 WeKnora 真实返回字段调整 `WeKnoraClient.parse_hits()`（已兼容 `data/results/hits` 三种结构）。

### 阶段 3（借鉴 personal_wxwork_ZTS 的细节）
- 每客户只保留**最新一条待人工确认内容**，带过期时间（避免队列越堆越多）。
- 分流原因与发送结果分开记录（本项目审计已分开：`action=escalate` / `action=send`）。
- 检索阈值必须用**自己的业务问答**重评，不能直接照搬它的相似度阈值。

## 四、数据边界（重要）

| 数据 | 放哪 | 谁维护 |
| --- | --- | --- |
| 产品说明、FAQ、售后政策 | 知识库（本地 md 或 WeKnora） | 业务 |
| 实时价格、库存、订单、物流 | 受控只读查询（`data/price_list.json` 或业务接口） | 系统 |
| 型号不明、图片无法判断、退款投诉 | 人工队列 + 暂停该会话自动回复 | 客服 |

## 五、验收标准（接完这些模块后）

1. 价格类问题：**100% 有依据或转人工**，不允许出现“无来源报价”。
2. OCR：真实截图上的型号/数字识别准确率不低于当前 RapidOCR（用同一批图对比）。
3. 知识库：任一答案都能回溯到“哪份资料、哪一段”；改文件后 `kb_reload` 能生效且版本号变化。
4. 接管：转人工后该客户**不再自动回复**，直到人工点“恢复自动”。
